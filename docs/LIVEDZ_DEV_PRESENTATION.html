1. Product & Channel Architecture

Three order intake channels converge into one multi-tenant PostgreSQL/Prisma pipeline with atomic stock reservation, Algerian phone/wilaya normalization, phone confirmation tracking, and courier integration.

Channel 1: QR / Product Link

/q/{cardToken} — Buyer picks variant, sees wilaya delivery rate, submits phone + address. Lands in DRAFT with atomic stock reserve.

Channel 2: TikTok Live + Claim Link

Worker parses comments (K1, كود3, K1 42) into expiring DRAFTs. Buyer completes coordinates at /l/{sessionToken} → PENDING_CONFIRMATION.

Channel 3: Manual Dashboard

Merchant enters phone/DM orders directly in the dashboard and manages all statuses through payout.

3. Critical Production Issues Resolved

Area Problem Identified Implemented Solution
Live Buyer Details TikTok comments lack phone/address; DRAFT orders strand without buyer info. Added /l/{sessionToken} claim portal. Buyer verifies @handle, sees reserved items & delivery fees, submits coordinates → PENDING_CONFIRMATION. Expired drafts release stock via sweeper.
Process Model In-memory Map breaks across serverless invocations and server restarts. Replaced with DB-backed LiveSession table, atomic FOR UPDATE SKIP LOCKED leases, 10s heartbeats, and standalone src/worker/live-worker.ts.
Courier Idempotency Rolling back timeouts to CONFIRMED risks creating duplicate parcels on retry. Added SHIPMENT_UNKNOWN state on timeouts/5xx, shipAttempts + shipmentAttemptKey (orderId-aN), Idempotency-Key header, and reconcileUnknownShipment().
Stock Consistency Conflicting reserve vs deduct semantics & comment spam locking inventory. Unified Reserve → Commit (SHIPPED) → Release (CANCELLED/EXPIRED) → Restock (RETURNED), plus 10-min per-viewer/product anti-spam dedup.
Algerian COD Ops Missing call attempts, return restocking, buyer risk flags, and wilaya fees. Built CallLog (auto-moves to AWAITING_CUSTOMER at 3 no-answers), BuyerReputation risk alerts, DeliveryRate per wilaya, and /api/webhooks/courier.
Parser Hardening Fixed K prefix, questions turned into orders, K1 42 size/qty ambiguity. Added full-width + Arabic/Persian digit normalization, configurable Merchant.liveCodePrefix, question detection to LiveQuestion, and catalog variant disambiguation.

4. Order State Machine & Stock Invariant

Invariant: available = stock - reserved ≥ 0 across all concurrent requests via conditional PostgreSQL UPDATE.

State Allowed Transitions Stock Effect
DRAFT PENDING_CONFIRMATION, CONFIRMED, NEEDS_INFO, AWAITING_CUSTOMER, CANCELLED, EXPIRED reserved += qty on create
PENDING_CONFIRMATION CONFIRMED, NEEDS_INFO, AWAITING_CUSTOMER, CANCELLED Stays reserved
CONFIRMED SHIPMENT_PENDING, CANCELLED Cancel → reserved -= qty
SHIPMENT_PENDING SHIPPED, CONFIRMED (4xx), SHIPMENT_UNKNOWN (timeout/5xx) Shipped → stock -= qty, reserved -= qty
SHIPMENT_UNKNOWN SHIPPED (reconciled), CONFIRMED (404), CANCELLED Reconciled shipped → deduct stock/reserved
SHIPPED / OUT_FOR_DELIVERY DELIVERED, RETURNED, FAILED Returned → stock += qty + rep flagged
DELIVERED CASH_COLLECTED, RETURNED Increments BuyerReputation.deliveredCount

5. Security & Dependency Risks

Risk Item Mitigation Implemented Follow-Up Plan
Unofficial TikTok Connector Wrapped behind LiveConnection interface; supports optional TIKTOK_SIGN_API_KEY & session cookie; labeled best-effort. Track error counters in LiveSession; configure EulerStream sign key for high-traffic lives.
DzShip Single Proxy Courier HTTP logic isolated in src/lib/couriers/dzship.ts; credentials decrypted only during dispatch/lookup. Implement direct Yalidine & ZR Express adapters behind a shared provider contract.
Encryption Key Rotation AES-256-GCM bound with AAD (merchantId:courier), v1. format, and CREDENTIALS_KEY_PREV key-ring fallback. Run periodic background re-encryption job when rotating primary key.
Webhook Integrity /api/webhooks/courier checks COURIER_WEBHOOK_SECRET using constant-time timingSafeEqual. Add per-courier HMAC signature validation once direct adapters ship.
